  [string[]]$FilePath, -Manifest, -InstallSendTo, -InstallKDE, -NoPause, -SystemWide, -Log, -Help

Dispatch routes:

  -InstallSendTo/-InstallKDE → lazy dot-source VeriHash.Integrations.ps1 → Install-*

  -Manifest + other files → New-VeriHashManifest
  Single file (no -Manifest) → Invoke-VeriHashHotPath
  Multiple files (no -Manifest) → Invoke-VeriHashBatch

  if (-not (Get-Module -Name $mod)) { Import-Module ... }

Test-VeriHashInteractive:
  Returns $true if launched from GUI shell, $false for terminal/redirected.

Describe 'End-to-end: manifest verify (CLI-03)' {

**Important implementation notes:**
- Set `-NoPause` on EVERY invocation of VeriHash.ps1 inside tests to prevent hanging on `Read-Host`
- Use `2>&1 | Out-String` to capture both stdout and stderr
- The clipboard tests (block 6) MUST be `-Skip:(-not $IsWindows)` since `Set-Clipboard` only works on Windows
- For manifest verify fail/missing tests, VeriHash.ps1 calls `exit $exitCode`. When invoked with `&`, PowerShell may throw a terminating error for non-zero exit. Use try/catch to capture the output OR use `$LASTEXITCODE` check instead
- Actually, `exit` inside a script invoked with `&` does NOT throw — it sets `$LASTEXITCODE`. So the try/catch wrapping is optional; just check `$LASTEXITCODE` instead:
  ```powershell
  $output = & $script:cliScript -FilePath $manifestPath -Manifest -NoPause 2>&1 | Out-String
  $LASTEXITCODE | Should -Be 1  # mismatch
  ```
  Use this pattern for the manifest verify fail and missing tests.
