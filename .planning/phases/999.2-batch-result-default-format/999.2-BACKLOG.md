# 999.2 — VeriHash.BatchResult default format view

**Status:** 🅿️ Backlog (parking lot — not yet scheduled)
**Source:** Phase 02 UAT (test 7) — cosmetic gap
**Created:** 2026-04-18

---

## Problem

`Invoke-VeriHashBatch` returns a `VeriHash.BatchResult` object to the pipeline. When the
function is called bare at an interactive prompt, PowerShell's default formatter renders
the entire object after the byte-locked tally line, e.g.:

```
1/1 matched, 0 mismatch, 0 missing

Results
-------
{@{FilePath=...; Hash=...; HashAlgorithm=SHA256; HashElapsedMs=0; Signature=error; ...
```

This is functionally correct (the object IS the documented return value, and tests assert
both the host-emitted tally line and the returned object's `Tally`/`TallyLine` fields),
but visually noisy for ad-hoc CLI users.

## Proposed fix

Add `VeriHash.HotPath/VeriHash.HotPath.format.ps1xml` defining a default view for
`VeriHash.BatchResult` that renders only `TallyLine` (or the three tally counts), hiding
the verbose `Results` array. Reference the file from the manifest via `FormatsToProcess`.

The same treatment can optionally be applied to `VeriHash.HotPathResult` (single-file
return), though that one is less noisy because its property set is flatter.

## Acceptance

- Calling `Invoke-VeriHashBatch -FilePath ... -Algorithm SHA256` interactively shows
  the per-file hash report blocks + the tally line + (at most) a one-line summary view
  of the returned object — no multi-line `Results -------` dump.
- Programmatic callers (`$b = Invoke-VeriHashBatch ...`) still get the full structured
  object unchanged. `$b.Results`, `$b.Tally`, `$b.TallyLine` all behave identically.
- `Tests/VeriHash.HotPath.Batch.Tests.ps1` continues to pass without modification
  (the tests inspect the structured object and capture `Write-Host` via streams,
  neither of which is affected by Format.ps1xml views).

## Notes

- Pure presentation — does NOT modify any function body, return shape, or logging.
- `Format.ps1xml` is auto-loaded when the manifest declares `FormatsToProcess`.
- The Phase 03 `Invoke-VeriHashBatch` consumers in 02-03-SUMMARY.md still see the
  byte-locked tally string in `$b.TallyLine`; this fix only alters the *default view*.
