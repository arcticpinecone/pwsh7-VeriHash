Create directory `.github/workflows/` if it does not exist, then create `.github/workflows/ci.yml` with the following exact content:

```yaml
name: CI

on:
  push:
    branches: [dev, main]
    paths:
      - '**.ps1'
      - 'Tests/**'
      - 'PSScriptAnalyzerSettings.psd1'
  pull_request:
    branches: [dev, main]
    paths:
      - '**.ps1'
      - 'Tests/**'
      - 'PSScriptAnalyzerSettings.psd1'
  workflow_dispatch:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    name: Tests (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]

    defaults:
      run:
        shell: pwsh

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install Pester
        run: |
          Set-PSRepository PSGallery -InstallationPolicy Trusted
          Install-Module Pester -Force -Scope CurrentUser -MaximumVersion 5.99

      - name: Run Pester Tests
        run: |
          $config = New-PesterConfiguration
          $config.Run.Path = './Tests'
          $config.Run.Exit = $true
          $config.Output.Verbosity = 'Detailed'
          Invoke-Pester -Configuration $config

  lint:
    name: PSScriptAnalyzer
    runs-on: ubuntu-latest

    defaults:
      run:
        shell: pwsh

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install PSScriptAnalyzer
        run: |
          Set-PSRepository PSGallery -InstallationPolicy Trusted
          Install-Module PSScriptAnalyzer -Force -Scope CurrentUser

      - name: Run PSScriptAnalyzer
        run: |
          $files = @(
              './VeriHash.ps1',
              './VeriHash.Config.ps1',
              './VeriHash.LogUtils.ps1'
          )
          $settings = './PSScriptAnalyzerSettings.psd1'
          $totalIssues = 0

          foreach ($file in $files) {
              $results = Invoke-ScriptAnalyzer -Path $file -Settings $settings
              if ($results) {
                  $totalIssues += $results.Count
                  Write-Host "❌ $file - $($results.Count) issue(s):" -ForegroundColor Red
                  $results | Format-Table RuleName, Severity, Line, Message -AutoSize
              } else {
                  Write-Host "✅ $file - Clean" -ForegroundColor Green
              }
          }

          if ($totalIssues -gt 0) {
              Write-Error "PSScriptAnalyzer found $totalIssues total issue(s)"
              exit 1
          }

          Write-Host "`n✅ All files pass PSScriptAnalyzer" -ForegroundColor Green
```

Design decisions implemented:
- Per D-01: Single workflow file (`ci.yml`)
- Per D-02: Triggers on push to `dev` and `main`, plus PRs targeting those branches
- Per D-03: Path filters on `**.ps1`, `Tests/**`, `PSScriptAnalyzerSettings.psd1` (settings file included because lint rule changes should trigger CI — agent discretion)
- Per D-04: Two parallel jobs (`test` and `lint`) with no dependency between them
- Per D-05: OS matrix `[ubuntu-latest, windows-latest]` — no macOS
- Per D-06: Latest pwsh only, no multi-version matrix
- Per D-07: `defaults.run.shell: pwsh` on both jobs — no Windows PowerShell 5.x
- Per D-08: Lint job runs `Invoke-ScriptAnalyzer` directly against all 3 files (not via Test-All.ps1)
- Per D-09: CI fails on findings via `exit 1` — the settings file's `Severity = @('Error', 'Warning')` ensures both severity levels are checked
- Per D-11: `Install-Module Pester -MaximumVersion 5.99` (CICD-04)
- Per D-12: `Install-Module PSScriptAnalyzer` at latest (no version pin)
- Per D-13: No module caching — fresh install each run
- Per D-14: PSFramework is NOT installed in CI

Agent discretion choices:
- `workflow_dispatch:` added for manual trigger capability (zero cost, useful for debugging)
- `concurrency` group with `cancel-in-progress: true` to save runner minutes on rapid pushes
- `fail-fast: false` so both OS jobs complete even if one fails (better diagnostics)
- `Set-PSRepository PSGallery -InstallationPolicy Trusted` before `Install-Module` to prevent interactive prompt hang (Pitfall 1)
- Pester `Run.Exit = $true` in its own step (not combined with other commands) per Pitfall 5
- Emoji-prefixed `Write-Host` output in lint job matches project reporting style from Test-All.ps1

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub event → workflow | Untrusted PR metadata could be injected into run blocks if referenced via `${{ github.event.* }}` |
| PSGallery → runner | Module downloads from public registry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | ci.yml `run:` blocks | accept | No `${{ github.event.* }}` interpolation in `run:` blocks — only static strings and PowerShell variables. No user-controlled input reaches shell execution. |
| T-02-02 | Tampering | PSGallery module install | accept | Pester and PSScriptAnalyzer are Microsoft-maintained, high-trust modules. Public repo — no secrets at risk. Version pin on Pester (`MaximumVersion 5.99`) limits attack surface. |
| T-02-03 | Information Disclosure | CI logs | accept | No secrets in workflow. Public repo — log output is expected to be visible. Hash values in test output are test fixtures, not real user data. |
</threat_model>
