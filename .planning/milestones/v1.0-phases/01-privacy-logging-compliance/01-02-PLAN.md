<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hash computation → Log output | Full SHA256 (64 chars) / SHA512 (128 chars) hash values cross into log files |
| Config path strings → Log output | OS paths containing usernames cross into structured log JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information Disclosure | Get-And-SaveHash line 839 | mitigate | Truncate hash to 16 chars + `...` via `$hashValue.Substring(0, [Math]::Min(16, $hashValue.Length)) + '...'` before passing to Write-PSFMessage (PRIV-01). Prevents file fingerprinting via hash correlation with known-file databases. |
| T-01-05 | Information Disclosure | VeriHash.Config.ps1 (11 sites) | mitigate | Pipe all ConfigDirectory and ConfigFile values through `ConvertTo-SanitizedPath` before logging. Replaces `C:\Users\username\...` with `%USERPROFILE%\...` (PRIV-02). Prevents username disclosure per GDPR Article 5(1)(c). |
| T-01-06 | Information Disclosure | PSFramework ComputerName/Username | accept | PSFramework adds ComputerName and Username metadata to every log entry. This cannot be disabled at the provider level (documented limitation in logging guide). Accepted because logs are local-only and user-controlled. |
</threat_model>
