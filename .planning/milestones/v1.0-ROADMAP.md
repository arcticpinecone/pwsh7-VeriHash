# Milestone v1.0: Privacy + Foundation

**Status:** ✅ SHIPPED 2026-04-18
**Phases:** 1-3
**Total Plans:** 6

## Overview

Close the audit gaps between the privacy-first logging guide and actual code, then lock in compliance with a CI/CD safety net. Three phases: fix what's broken, automate the guard rails, bundle the remaining small wins.

## Phases

### Phase 1: Privacy & Logging Compliance

**Goal**: All log output complies with the privacy-first logging guide — no full hashes, no raw paths, single bootstrap
**Depends on**: Nothing (first phase)
**Requirements**: PRIV-01, PRIV-02, PRIV-03, PRIV-04, LOGC-02
**Plans**: 3 plans

Plans:
- [x] 01-01: Relocate ConvertTo-SanitizedPath to LogUtils, reorder dot-sources, deduplicate PSFramework bootstrap
- [x] 01-02: Fix hash truncation (PRIV-01) and config path sanitization (PRIV-02)
- [x] 01-03: Update logging guide to match actual code behavior (PRIV-04)

**Success Criteria (verified):**
1. ✅ Hash values truncated to 16 chars + `...` in all log output
2. ✅ Config operations sanitize all paths via `ConvertTo-SanitizedPath`
3. ✅ `ConvertTo-SanitizedPath` defined in `VeriHash.LogUtils.ps1`, callable cross-module
4. ✅ Single PSFramework bootstrap detection — no redundant `Get-Module` calls
5. ✅ Logging guide describes actual behavior with zero caveats

**Key Decisions:**
- Logging guide is the contract; fix code to match (✅ Good — closed all privacy gaps)
- Defer monolith split to its own milestone (✅ Good — kept scope focused)
- Bundle small wins into milestone (✅ Good — closed cheaply under CI protection)
- CI/CD before new features (✅ Good — every push now auto-validated)
- Expand PSScriptAnalyzer to all 3 modules (✅ Good — full lint coverage)

- LOGC-02 grouped with Phase 1 (✅ Good — shared dot-source changes)
